# 2026-IoT · FedACG 공격·방어 연구 (mobicom)

서버 모멘텀을 쓰는 FedACG가 공격에 더 취약한지, 강건 집계(Krum, Multi-Krum, Trimmed Mean, Median)를 붙였을 때 효율과 보안을 함께 지킬 수 있는지 검증한다.

- 구현 기반: [FedACG (CVPR 2024)](https://github.com/geehokim/FedACG)
- 서베이: The Impact of Adversarial Attacks on Federated Learning: A Survey (IEEE TPAMI 2024)

## 작업 규칙
- 각자 작업 브랜치에서 작업하고 PR로 합친다.
- 실험 설정은 설정 파일에 모으고 코드 안에 숫자를 직접 쓰지 않는다.
- 결과 파일 이름: `알고리즘_집계_공격_비율_시드.csv` (예: `fedacg_krum_lf_20_s1.csv`)

## 1차 실험 계획 (2026-11-19 ~ 11-22, 사흘)

무료 코랩 T4로 사흘 안에 끝낼 수 있는 분량으로 잡은 1차 계획이다. 가이드의 전체 조합(비율 3종 × 시드 3회)은 2차로 이어서 돌린다.

### 근거 (코랩 T4 실측)
- 라운드당 약 47~49초(클라이언트 10명 × 로컬 5 epoch, FedACG + Krum)
- `num_workers=2`는 오히려 3.5배 이상 느렸다. FedACG가 `spawn` 방식으로 데이터 로더를 클라이언트마다 새로 만들기 때문이다. 그래서 `num_workers=0`(기본)을 쓴다.
- 무료 코랩 GPU 시간은 1인당 하루 약 4시간으로 보수적으로 잡았다(끊김과 재연결 손실 포함). 1인당 사흘이면 약 12시간이다.

### 설정 (팀 전체 공통)
| 항목 | 1차 값 | 가이드 원래 값 |
|---|---|---|
| 라운드 수 | **80** | 미정 (FedACG 논문은 1000) |
| 공격 구간 | **30 ≤ r < 50** (공격 전 30, 공격 20, 회복 30라운드) | 미정 |
| 악성 비율 | **20%** 먼저 | 10%, 20%, 30% |
| 시드 | **1** 먼저 | 3회 평균 |

노트북 5번 셀의 기본값(`ROUNDS = 80`, `EXTRA = 'attack.start_round=30 attack.end_round=50'`)이 이 설정이다.

### 분담 (1인당 10개, 약 11시간)
| 사람 | `SPEC` | 1차 실행 |
|---|---|---|
| 강윤서 | `baseline_sweep.yaml` | 무공격 기준선, 2 알고리즘 × 5 집계, 시드 1 |
| 예다은 | `lf_sweep.yaml` | 라벨 플리핑 20%, 2 × 5, 시드 1 |
| 우은식 | `mp_sweep.yaml` | 모델 오염 20%, 2 × 5, 시드 1 |

- 실행 대기열이 이 순서(시드 1의 20% 먼저)로 정렬되어 있다. 각자 5번 셀을 돌리면 처음 10개가 정확히 1차 분량이다.
- 1차가 끝나면 같은 셀을 계속 돌려 2차로 넘어간다. 순서는 시드 1의 10%·30% → 시드 2 → 시드 3이다.
- 결과는 공유 드라이브 폴더 `MyDrive/2026-IoT/results`에 모은다(노트북 5번 셀 설명 참고).

### 한계 (5장에 적을 것)
- 80라운드는 FedACG 논문(1000라운드)보다 훨씬 짧아 절대 정확도가 낮다. 이 연구는 같은 조건끼리의 비교(정확도 하락, 회복 라운드, ‖m‖ 추이)를 본다.
- 1차 결과는 악성 비율 20%, 시드 1회 기준이다.
